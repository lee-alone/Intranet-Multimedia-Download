### 3. 批量任务进度聚合

**聚合逻辑**:
```go
// 统计各状态数量
switch engine.TaskStatus(taskStatus) {
case engine.TaskStatusCompleted:
    completed++
case engine.TaskStatusFailed:
    failed++
case engine.TaskStatusCancelled:
    cancelled++
case engine.TaskStatusQueued:
    queued++
case engine.TaskStatusDownloading, engine.TaskStatusMerging:
    downloading++
}

// 计算整体进度
overallProgress = float64(completed+failed+cancelled) / float64(total) * 100
```

**批量任务状态转换**:
- `pending`: 初始状态
- `processing`: 任务开始执行
- `completed`: 所有任务成功完成
- `partial`: 部分任务完成，部分失败/取消
- `failed`: 所有任务失败

### 5. 取消清理策略实现

**临时文件清理逻辑**:
```go
func cleanupTempFiles(filePath string) error {
    dir := filepath.Dir(filePath)
    baseName := strings.TrimSuffix(filepath.Base(filePath), filepath.Ext(filePath))
    
    // 清理相关的临时文件
    patterns := []string{
        filePath + ".part",
        filePath + ".temp",
        filepath.Join(dir, baseName+".part*"),
        filepath.Join(dir, baseName+".temp*"),
        filepath.Join(dir, baseName+".f*.part"),
        filepath.Join(dir, baseName+".f*.temp"),
    }
    
    // 删除匹配的文件
    for _, pattern := range patterns {
        matches, _ := filepath.Glob(pattern)
        for _, match := range matches {
            os.Remove(match)
        }
    }
    
    // 删除主文件
    if _, err := os.Stat(filePath); err == nil {
        os.Remove(filePath)
    }
    
    return nil
}
```

**清理策略**:
- 清理 `.part` 和 `.temp` 临时文件
- 清理分片下载产生的临时文件（`.f*.part`）
- 清理主文件（如果存在）
- 清理失败不影响任务取消操作

**代码位置**: [`internal/handler/task.go:509-549`](internal/handler/task.go)

## 🔧 技术要点

### 1. UUID 作为主键

使用 `github.com/google/uuid` 包生成 UUID 作为任务 ID 和批量任务 ID：

```go
import "github.com/google/uuid"

batchID := uuid.New().String()
taskID := uuid.New().String()
```

**优点**:
- 全局唯一，避免 ID 冲突
- 无需数据库自增序列
- 支持分布式系统

---

### 2. URL 验证正则

```go
var urlRegex = regexp.MustCompile(`^https?://[^\s]+$`)

// 使用示例
if !urlRegex.MatchString(url) {
    return fmt.Errorf("无效的 URL 格式")
}
```

### 3. 临时文件清理策略

patterns := []string{

for _, pattern := range patterns {

---

### 4. 批量任务状态机

```
pending → processing → completed
                      → partial
                      → failed
```

**状态转换条件**:
- `pending` → `processing`: 第一个任务开始执行
- `processing` → `completed`: 所有任务成功完成
- `processing` → `partial`: 部分任务完成，部分失败/取消
- `processing` → `failed`: 所有任务失败
