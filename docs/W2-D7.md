### Bug 1: 故障转移引擎死锁问题（严重）

**问题描述**: `recordFailure` 方法在持有锁的情况下调用 `switchEngine`，而 `switchEngine` 也尝试获取锁，导致死锁。

**影响**: 
- `TestFailoverEngine_SwitchEngine` 测试卡死
- `TestFailoverEngine_ResetEngine` 测试卡死
- 实际运行时触发故障转移会导致程序挂起

**修复方案**: 创建内部版本方法 `switchEngineLocked()` 和 `getEngineHealthLocked()`，假设调用者已持有锁。

**修复代码**:
```go
// 修复前：死锁
func (fe *FailoverEngine) recordFailure(...) {
    fe.mu.Lock()
    defer fe.mu.Unlock()
    // ...
    fe.switchEngine()  // ← 尝试再次加锁，死锁！
}

func (fe *FailoverEngine) switchEngine() {
    fe.mu.Lock()       // ← 死锁位置
    defer fe.mu.Unlock()
    // ...
}

// 修复后：使用内部版本
func (fe *FailoverEngine) recordFailure(...) {
    fe.mu.Lock()
    defer fe.mu.Unlock()
    // ...
    fe.switchEngineLocked()  // ← 调用内部版本，不再加锁
}

func (fe *FailoverEngine) switchEngine() {
    fe.mu.Lock()
    defer fe.mu.Unlock()
    fe.switchEngineLocked()  // 公开版本，会加锁
}

func (fe *FailoverEngine) switchEngineLocked() {
    // 内部版本，假设调用者已持有锁
    // ... 切换逻辑 ...
}
```

**修复后测试**: 所有测试通过，无死锁。

### Bug 2: 任务调度器死锁问题（严重）

**问题描述**: `CancelTask` 方法在持有写锁的情况下调用 `notifyTaskUpdate`，而 `notifyTaskUpdate` 尝试获取读锁，导致死锁。

**影响**:
- `TestTaskScheduler_CancelTask` 测试卡死
- 实际运行时取消任务会导致程序挂起

**修复方案**: 创建内部版本方法 `notifyTaskUpdateLocked()`，假设调用者已持有锁。

**修复代码**:
```go
// 修复前：死锁
func (s *TaskScheduler) CancelTask(taskID string) error {
    s.mu.Lock()
    defer s.mu.Unlock()
    // ...
    s.notifyTaskUpdate(task)  // ← 尝试获取读锁，死锁！
}

func (s *TaskScheduler) notifyTaskUpdate(task *Task) {
    s.mu.RLock()  // ← 死锁位置
    defer s.mu.RUnlock()
    // ...
}

// 修复后：使用内部版本
func (s *TaskScheduler) CancelTask(taskID string) error {
    s.mu.Lock()
    defer s.mu.Unlock()
    // ...
    s.notifyTaskUpdateLocked(task)  // ← 调用内部版本
}

func (s *TaskScheduler) notifyTaskUpdateLocked(task *Task) {
    // 内部版本，假设调用者已持有锁
    callback := s.onTaskUpdate
    if callback != nil {
        callback(task)
    }
}
```

**修复后测试**: 所有测试通过，无死锁。

### 1. 故障转移机制 (`internal/engine/failover.go`)

**文件**: [`internal/engine/failover.go`](internal/engine/failover.go)

实现了完整的故障转移机制，包括：

#### 核心结构

```go
// FailoverConfig 故障转移配置
type FailoverConfig struct {
    MaxFailures      int           // 最大失败次数阈值
    FailureWindow    time.Duration // 失败时间窗口
    CooldownTime     time.Duration // 冷却时间
    EnableAutoSwitch bool          // 是否启用自动切换
    EnableAlert      bool          // 是否启用告警
}

// EngineHealth 引擎健康状态
type EngineHealth struct {
    Name           string
    Status         EngineStatus
    FailureCount   int
    LastFailure    time.Time
    LastSuccess    time.Time
    IsHealthy      bool
    CooldownUntil  time.Time
    Version        string
    VersionChecked time.Time
}
```

#### 功能特性

1. **连续失败计数器**
   - 记录每次下载失败的时间、URL、错误信息
   - 自动清理过期记录（基于 `FailureWindow` 配置）
   - 实时统计失败次数

2. **引擎切换逻辑**
   - 当失败次数达到阈值时自动切换到备用引擎
   - 支持冷却时间防止频繁切换
   - 提供手动重置功能恢复主引擎

3. **版本检测与热更新**
   - 缓存引擎版本信息（5 分钟有效期）
   - 支持版本检查和更新通知
   - 提供 `CheckAndUpdateVersion` 方法

4. **故障转移告警**
   - 支持告警回调函数
   - 告警类型包括：`failover`（切换）、`reset`（重置）、`update`（更新）
   - 可配置是否启用告警

#### 使用方法

```go
// 创建故障转移引擎
primary := NewYtdlpEngine(YtdlpConfig{})
backup := NewLuxEngine(LuxConfig{})

config := FailoverConfig{
    MaxFailures:      3,
    FailureWindow:    5 * time.Minute,
    CooldownTime:     1 * time.Minute,
    EnableAutoSwitch: true,
    EnableAlert:      true,
}

failoverEngine := NewFailoverEngine(primary, backup, config)

// 设置告警回调
failoverEngine.SetAlertCallback(func(alertType, message string) {
    log.Printf("告警 [%s]: %s", alertType, message)
})

// 设置健康状态变化回调
failoverEngine.SetHealthChangeCallback(func(engineName string, health *EngineHealth) {
    log.Printf("引擎 %s 健康状态变化：%+v", engineName, health)
})

// 使用故障转移引擎下载
progressChan := failoverEngine.Download(ctx, url, options)
```

### 2. 任务调度器 (`internal/engine/scheduler.go`)

**文件**: [`internal/engine/scheduler.go`](internal/engine/scheduler.go)

实现了基于 Channel 模型的任务调度器，支持并发控制和任务状态管理。

#### 核心结构

```go
// TaskStatus 任务状态
type TaskStatus string

const (
    TaskStatusQueued      TaskStatus = "queued"      // 排队中
    TaskStatusDownloading TaskStatus = "downloading" // 下载中
    TaskStatusMerging     TaskStatus = "merging"     // 合并中
    TaskStatusCompleted   TaskStatus = "completed"   // 已完成
    TaskStatusFailed      TaskStatus = "failed"      // 失败
    TaskStatusCancelled   TaskStatus = "cancelled"   // 已取消
)

// TaskPriority 任务优先级
type TaskPriority int

const (
    PriorityLow    TaskPriority = 0
    PriorityNormal TaskPriority = 1
    PriorityHigh   TaskPriority = 2
    PriorityUrgent TaskPriority = 3
)

// Task 下载任务
type Task struct {
    ID          string
    URL         string
    Options     DownloadOptions
    Priority    TaskPriority
    Status      TaskStatus
    Progress    DownloadProgress
    Engine      string
    BatchID     string        // 批量任务 ID
    CreatedAt   time.Time
    StartedAt   time.Time
    CompletedAt time.Time
    Error       error
}
```

#### 功能特性

1. **任务状态机**
   ```
   queued → downloading → merging → completed
                      ↓
                   failed
                      ↓
                 cancelled
   ```

2. **并发控制**
   - 使用信号量（Semaphore）限制并发数
   - 默认最大并发 10 个任务
   - 可配置调整

3. **优先级队列**
   - 支持 4 个优先级：Low、Normal、High、Urgent
   - 高优先级任务优先执行
   - 同优先级按 FIFO 顺序

4. **批量任务支持**
   - `BatchScheduler` 支持批量任务管理
   - 整体进度聚合
   - 子任务状态独立跟踪

#### 使用方法

```go
// 创建调度器
engine := NewYtdlpEngine(YtdlpConfig{})
config := SchedulerConfig{
    MaxConcurrent: 10,
    QueueSize:     100,
}
scheduler := NewTaskScheduler(engine, config)

// 设置任务更新回调
scheduler.SetTaskUpdateCallback(func(task *Task) {
    log.Printf("任务 %s 状态更新：%s", task.ID, task.Status)
})

// 添加任务
task := &Task{
    ID:       "task-001",
    URL:      "https://www.bilibili.com/video/BV1xx",
    Priority: PriorityNormal,
    Options: DownloadOptions{
        OutputDir: "./downloads",
        Quality:   "1080p",
    },
}
scheduler.AddTask(task)

// 获取任务
task, err := scheduler.GetTask("task-001")

// 取消任务
err = scheduler.CancelTask("task-001")

// 获取队列
queue := scheduler.GetQueue()

// 清理已完成任务
count := scheduler.ClearCompletedTasks()
```

## 🔧 技术细节

### 故障转移机制

1. **失败记录管理**
   - 使用滑动时间窗口（`FailureWindow`）清理过期记录
   - 每次失败记录包含：时间戳、URL、错误信息、引擎名称

2. **引擎切换策略**
   - 当失败次数达到 `MaxFailures` 时触发切换
   - 切换前检查备用引擎是否在冷却期
   - 切换后发送 `failover` 告警

3. **健康状态跟踪**
   - 实时计算引擎健康状态
   - 基于失败次数和冷却时间判断健康度

### 任务调度器

1. **并发控制实现**
   - 使用带缓冲的 channel 作为信号量
   - `semaphore := make(chan struct{}, MaxConcurrent)`
   - 获取信号量：`semaphore <- struct{}{}`
   - 释放信号量：`<-semaphore`

2. **优先级队列**
   - 使用切片存储待执行任务
   - 插入时按优先级排序（高优先级在前）
   - 支持动态调整优先级

3. **任务状态管理**
   - 使用 `sync.RWMutex` 保护并发访问
   - 状态变更触发回调通知
   - 支持状态查询和转换
