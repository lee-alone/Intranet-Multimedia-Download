校园资源采集系统 (Resource Collector) 技术立项与开发白皮书 v4.0
================================================================

1. 执行摘要
----------------------------------------------------------------
本系统旨在解决校园内网环境下，教师获取第三方平台（如 Bilibili、国家中小学智慧教育平台等）教学视频资源的痛点。系统采用"服务端中转、客户端直存"的逻辑，结合现代化的 Web 交互与高性能的后端调度，提供一个安全、受控、免安装的视频采集方案。

2. 核心设计原则
----------------------------------------------------------------
模块化解耦：核心逻辑、下载引擎、UI 界面与外部依赖完全分离，确保系统具备长期迭代能力。

零足迹存储：服务器不建立长期视频库，仅负责数据中转，降低版权积压风险与磁盘压力。

双平台交付：原生支持 Windows 64-bit 与 Linux 64-bit，不依赖 Docker，适配各类校园内网服务器。

合规与审计：内置用户鉴权、访问日志与合理使用协议，满足校园信息安全要求。

可观测性优先：健康检查、指标暴露、日志告警三位一体，降低运维成本。

3. 技术架构与模块化设计
----------------------------------------------------------------
3.1 技术栈 (Technology Stack)

| 层级       | 选型                          | 说明                                      |
|------------|-------------------------------|-------------------------------------------|
| 后端       | Go (Golang) 1.20+             | 负责调度、API、嵌入式资源                  |
| 前端       | Vue 3 + Tailwind CSS          | 现代化、极简、高响应比 UI                  |
| 主引擎     | yt-dlp (PyInstaller 独立打包) | 覆盖 4000+ 站点，无需 Python 运行时依赖     |
| 备用引擎   | Lux (Go 原生)                 | 国内平台补充，轻量快速                      |
| 多媒体     | FFmpeg 静态包                 | 执行封装、合并、转码                        |
| 数据       | SQLite 3 (WAL 模式)           | 存储用户、配置与任务流水                    |
| 缓存       | Go Channel + Ring Buffer      | WebSocket 消息缓冲、任务队列                |
| 认证       | JWT Token (RS256)             | 无状态认证，支持刷新令牌                    |

3.3 引擎故障转移策略 (Engine Failover Policy)

| 故障场景                  | 触发条件                          | 切换动作            | 回切策略                  |
|---------------------------|-----------------------------------|---------------------|---------------------------|
| 解析失败                  | yt-dlp 返回非零退出码             | 立即切换 Lux        | 下次任务优先 yt-dlp       |
| 下载超时                  | 单任务超过 config.timeout 秒      | 切换 Lux 重试       | 下次任务优先 yt-dlp       |
| 特定域名                  | URL 命中 Lux 优化域名列表         | 直接分配 Lux        | 保持 Lux                  |
| yt-dlp 版本过旧           | 版本 < config.min_version         | 触发自动更新        | 更新完成后切回 yt-dlp     |
| 连续失败 3 次             | 同一引擎连续 3 任务失败            | 切换引擎 + 告警     | 需管理员手动确认回切      |
| runtime/yt-dlp 缺失       | 启动自检或调用时文件不存在        | 切换 Lux + 告警     | 文件恢复后自动切回        |

引擎优先级配置 (config.yaml)：
```yaml
engine:
  primary: "yt-dlp"
  fallback: "lux"
  auto_failover: true
  failover_threshold: 3
  min_version: "2024.01.01"     # 最低版本要求（语义化版本比较）
  update_check_interval: "24h"  # 版本检查间隔
  domain_override:
    "ixigua.com": "lux"
    "douyin.com": "lux"
```

版本比较逻辑：
- 使用语义化版本比较（semver），格式：YYYY.MM.DD[.PATCH]
- 示例：2024.01.01 < 2024.03.15 < 2025.01.01

3.4 WebSocket 连接管理策略

| 机制           | 配置参数                    | 说明                                      |
|----------------|-----------------------------|-------------------------------------------|
| 心跳检测       | heartbeat_interval: 30s     | 每 30 秒发送 Ping，3 次无响应则断开         |
| 断线重连       | max_reconnect: 5            | 客户端最多重连 5 次，指数退避 (1s/2s/4s...) |
| 消息缓冲       | buffer_size: 100            | 服务端缓冲最近 100 条进度消息               |
| 离线缓存       | cache_offline: true         | 客户端离线时缓存进度，重连后补发            |
| 消息去重       | dedup_window: 5s            | 5 秒内相同进度只推送一次                    |

WebSocket 端点：
```
WS /api/v1/ws/tasks/{task_id}/progress    # 单任务进度订阅
WS /api/v1/ws/tasks/progress              # 全部任务进度订阅（批量场景）
```

连接建立后，服务端推送消息格式：
```json
{
  "task_id": "task_abc123",
  "status": "downloading",
  "progress": 45.5,
  "speed_mbps": 2.5,
  "eta_seconds": 120
}
```

4. 业务流程与功能规范
----------------------------------------------------------------
4.1 认证方式说明

系统采用 JWT Token 认证机制：

| 令牌类型     | 有效期    | 用途                  | 刷新机制              |
|--------------|-----------|-----------------------|-----------------------|
| Access Token | 2 小时    | API 请求认证          | 使用 Refresh Token 换取 |
| Refresh Token| 7 天      | 刷新 Access Token     | 过期后需重新登录      |

认证流程：
1. 用户 POST /api/v1/login 提交凭据
2. 服务端验证后返回 access_token 和 refresh_token
3. 前端将 access_token 存入内存，refresh_token 存入 HttpOnly Cookie
4. 后续 API 请求在 Authorization 头携带：Bearer <access_token>
5. Token 过期时，自动调用 POST /api/v1/token/refresh 刷新

4.2 视频下载流程

(1) 用户准入
    - 支持本地 SQLite 账号或校园 LDAP/SSO 统一身份认证登录
    - SSO 失败降级策略：LDAP 不可用时自动切换至本地账号认证
    - 首次登录强制勾选《校园教学资源合理引用协议》，同意记录写入 data.db

(2) 智能嗅探
    - 通用平台：自动解析标题、缩略图、多清晰度选项
    - 封闭平台 (如微信)：前端识别 URL 并弹出提示框，引导使用 res-downloader 客户端
    - 域名白名单校验：config.yaml 配置可下载域名范围，非白名单 URL 拒绝解析

(3) 下载与进度
    - 后端通过 WebSocket 实时推送加权平滑后的进度百分比
    - 批量任务支持"总进度 + 单任务进度"双层展示
    - 支持断点续传（基于 yt-dlp 原生能力）
    - 支持任务优先级调整和单个任务取消

(4) 浏览器保存
    - 合并完成后，服务器流式推送到前端
    - 输出文件名自动添加【教学引用】前缀
    - 由老师保存至个人电脑本地

4.3 安全与风险控管

| 控制项         | 实现方案                                              |
|----------------|-------------------------------------------------------|
| 域名白名单     | config.yaml 配置，启动时加载至内存，每次请求校验       |
| 配置防篡改     | 启动时检测 config.yaml 文件权限（Windows 仅 Administrators 可写） |
| 敏感配置加密   | LDAP 密码等字段支持环境变量引用 ${LDAP_PASSWORD}       |
| 源码保护       | Go 二进制混淆编译 (-ldflags="-s -w")，前端资源静态嵌入  |
| 审计日志       | 保留 180 天，URL 敏感参数自动脱敏                      |
| 日志访问控制   | 需 admin 角色 + 二次鉴权（TOTP MFA）                   |
| SSO 降级       | LDAP 不可用时自动切换本地认证，记录降级事件至审计日志   |
| 单用户带宽限制 | config.yaml 配置 per_user_bandwidth，防止过度占用      |
| 单任务超时     | config.yaml 配置 task_timeout，超时自动终止并释放资源  |

4.4 日志脱敏规则

| 字段类型       | 脱敏规则                          | 示例                      |
|----------------|-----------------------------------|---------------------------|
| URL 参数       | token、sessionid、key 等参数值掩码 | token=abc***123           |
| 用户密码       | 完全不记录                        | -                         |
| IP 地址        | 后两段掩码（内网可配置保留）       | 192.168.***.***           |
| LDAP DN        | 保留结构，值部分掩码              | cn=adm***,ou=users        |

4.5 MFA 实现方案

查看审计日志需 TOTP（Time-based One-Time Password）二次验证：

1. 管理员首次启用 MFA：
   - 调用 POST /api/v1/mfa/enable 获取 TOTP 密钥和二维码
   - 使用认证器 App（Google Authenticator / Microsoft Authenticator）扫描二维码
   - 输入 6 位验证码完成绑定
   - 保存备用恢复码（10 个，单次使用）

2. 查看审计日志流程：
   - 调用 POST /api/v1/audit-logs/verify 提交当前 TOTP 验证码
   - 验证通过后获得 30 分钟临时审计权限
   - 临时权限期间无需重复验证

3. 配置项：
```yaml
security:
  audit:
    mfa_required: true
    mfa_type: "totp"           # 支持 totp / email
    session_duration: "30m"    # MFA 验证后有效期
```

7. 性能压测计划
----------------------------------------------------------------
W4 压测场景细化：

| 测试项                  | 目标                          | 通过标准                    |
|-------------------------|-------------------------------|-----------------------------|
| 10 并发下载             | 同时 10 个任务不崩溃           | 无 OOM，CPU<80%             |
| FFmpeg 合并峰值内存     | 单任务内存上限控制             | 单任务<500MB，总<4GB        |
| WebSocket 消息吞吐      | 10 任务×1 秒进度推送           | 前端渲染无卡顿，延迟<200ms  |
| SQLite WAL 写入         | 1000 条审计日志连续写入        | 无锁竞争，写入延迟<50ms     |
| 引擎热更新              | yt-dlp 在线检测与下载          | 更新过程不影响现有任务      |
| SSO 降级切换            | LDAP 超时后自动切本地          | 切换时间<3 秒，用户无感知    |
| 磁盘告警触发            | 缓存达 80% 容量                | 正确触发告警，日志可查      |
| 日志轮转                | 单文件超 100MB 自动分割         | 历史日志 7 天后压缩          |
| JWT 刷新并发            | 100 用户同时刷新 Token         | 无失败，延迟<100ms          |

FFmpeg 内存限制策略：
- 合并阶段：单任务内存上限 500MB（通过 --limit-mem 或外部 cgroup 控制）
- 下载阶段：单任务缓冲上限 16MB（config.task.download_buffer_mb）
- 串行化：当活跃转码任务>3 时，新任务进入等待队列
- 临时文件分片：大文件分段处理，避免单次加载全部数据

流式传输内存控制：
- 服务端不缓存完整文件，使用 io.Copy 流式转发
- 客户端边接收边保存，服务端内存占用为 0（除 TCP 缓冲区）

8. API 接口文档
----------------------------------------------------------------
8.1 RESTful API 端点

| 方法 | 端点                    | 说明                  | 认证要求      |

9. 错误处理规范
----------------------------------------------------------------
9.1 全局错误码定义

| 错误码范围   | 类别              | HTTP 状态码 | 说明                      |
|--------------|-------------------|-------------|---------------------------|
| E001-E099    | 系统错误          | 500         | 内部异常、数据库错误等    |
| E100-E199    | 认证授权错误      | 401/403     | 登录失败、权限不足等      |
| E200-E299    | 任务错误          | 400/404     | 下载失败、解析失败等      |
| E300-E399    | 资源错误          | 404/507     | 文件不存在、磁盘满等      |
| E400-E499    | 配置错误          | 400/403     | 白名单限制、引擎不可用等  |

9.2 常见错误码与友好提示

| 错误码 | HTTP 状态码 | 技术信息                          | 用户提示                      |
|--------|-------------|-----------------------------------|-------------------------------|
| E001   | 500         | internal server error             | 系统繁忙，请稍后重试          |
| E002   | 500         | database connection failed        | 数据库连接失败，请联系管理员  |
| E101   | 401         | invalid credentials               | 用户名或密码错误              |
| E102   | 401         | ldap connection timeout           | 认证服务暂时不可用            |
| E103   | 403         | insufficient permissions          | 您没有权限执行此操作          |
| E104   | 401         | token expired                     | 登录已过期，请重新登录        |
| E201   | 400         | url parse failed                  | 无法解析该链接，请检查格式    |
| E202   | 408         | download timeout                  | 下载超时，请尝试稍后重试      |
| E203   | 503         | engine failover triggered         | 正在切换备用引擎，请稍候      |
| E301   | 404         | file not found                    | 文件不存在或已过期清理        |
| E302   | 507         | disk space insufficient           | 服务器存储空间不足            |
| E401   | 403         | domain not in whitelist           | 该网站不在允许下载范围内      |
| E402   | 400         | platform not supported            | 该平台暂不支持，请使用本地工具 |

9.3 异常捕获策略
- 所有 API 返回统一 JSON 格式，包含 code、message、data
- 技术细节记录至审计日志，用户侧仅展示友好提示
- 未捕获异常统一返回 E001，避免暴露堆栈信息

9.4 任务取消清理策略

DELETE /api/v1/tasks/:id 取消任务时，根据任务状态执行不同清理逻辑：

| 任务状态       | 清理动作                                              |
|----------------|-------------------------------------------------------|
| queued         | 从队列移除，无残留                                    |
| downloading    | 终止下载进程，删除部分下载文件，释放带宽              |
| merging        | 等待 FFmpeg 当前分片完成，终止后续合并，清理临时文件  |
| completed      | 返回错误：任务已完成，无法取消                        |

清理保证：
- 使用 defer 确保临时文件删除
- 清理失败记录审计日志，由 Janitor 定时扫描清理
- 支持手动强制清理：DELETE /api/v1/tasks/:id?force=true

10.2 回滚方案

版本升级失败时的回滚步骤：

1. 停止当前服务：systemctl stop collector 或 任务管理器结束进程
2. 备份当前数据：
   - 备份 data.db 至安全位置
   - 备份 config.yaml 和 config.env
   - 备份 audit_logs/（如需保留最新审计记录）
3. 恢复旧版本：
   - 替换 collector[.exe] 为上一版本
   - 恢复 runtime/ 目录至旧版本
4. 回滚数据库（如有 schema 变更）：
   - 使用备份的 data.db 覆盖
5. 重启服务并验证：
   - 启动旧版本服务
   - 验证 /health 端点
   - 验证登录和下载功能

10.4 告警渠道配置

Webhook 请求格式：
```json

{
  "alert_type": "disk_warning",
  "severity": "warning",
  "timestamp": "2026-03-25T10:00:00Z",

  "details": {
    "path": "./temp_cache",
    "used_percent": 80,
    "used_gb": 40,
    "total_gb": 50
  }
}
```

告警类型：
- disk_warning：磁盘使用率超阈值
- disk_critical：磁盘已满，拒绝新任务
- engine_failover：引擎故障转移触发
- ldap_unavailable：LDAP 服务不可用
- task_timeout：任务超时
- cleanup_failed：清理任务失败
